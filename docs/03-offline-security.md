# 社内環境への持ち込みと依存管理

## 設計方針

このリポジトリは、ビルド時に外部リポジトリへ接続しません。

- Maven Wrapper、`pom.xml`、Gradle Wrapperを置かない
- JUnitを使わず、Javaだけで動く小さなテストランナーを使う
- jCardSim JARをバージョン固定して同梱する
- `scripts/build.ps1`がJARのSHA-256を毎回検証する
- Oracle JDK／Java Card Toolsは社内のソフトウェア配布手順で別途導入する

## 持ち込み前に確認するもの

会社のセキュリティルールを優先し、管理部門が求める承認、ウイルス検査、SBOM登録などを行います。

| 対象 | 確認ポイント |
| --- | --- |
| ソース | GitHub上のコミットID、レビュー結果 |
| jCardSim | `com.klinec:jcardsim:3.0.6.0`、Apache 2.0、SHA-256 |
| JDK | ベンダー、バージョン、配布元、更新方針 |
| Java Card Tools | Oracle配布元、バージョン、ライセンス |
| VS Code拡張 | 発行元、拡張ID、社内許可リスト |

同梱JARの期待値は`lib/SHA256SUMS`にも記録しています。

```text
db6de7ffde71651c45d00df7e160771685cec3e14e444bf36b796658d289942f
```

## JARをリポジトリに置けない会社の場合

会社の規則でバイナリのGit登録が禁止される場合は、`lib/jcardsim-3.0.6.0.jar`だけを削除し、承認済みの社内アーティファクト保管庫から同じパスへ配布します。ファイル名とSHA-256は変えないため、ソースやスクリプトの変更は不要です。

チェックサムは改ざんの検出には役立ちますが、ライブラリが安全であること自体を証明するものではありません。採用可否は会社の審査に従います。
